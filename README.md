# AI Agent Security — Multi-Step Tool Attacks

A competition entry and research working note for the Kaggle competition
[*AI Agent Security: Multi-Step Tool Attacks*](https://www.kaggle.com/competitions/ai-agent-security-multi-step-tool-attacks)
(hosted by OpenAI, Google, and IEEE). The task is algorithmic red-teaming of tool-using AI agents in
a deterministic offline benchmark: an `attack.py` search algorithm produces replayable attack
candidates that the evaluator re-runs and scores against four security predicates
(exfiltration, untrusted-to-action, destructive write, confused deputy).

## What's here

- **[`paper/working_note.md`](paper/working_note.md)** — the research working note. A source-audited
  account of the benchmark with two headline findings:
  1. **Guardrail–predicate asymmetries** — the public guardrail and the scoring predicates inspect
     different trace fields, sinks, and time windows; the resulting four-part taxonomy doubles as a
     defensive checklist for making policy and measurement agree.
  2. **A throughput plateau** — across the tested attack family (single-post, packing, forging,
     probe-hop), public score tracks the candidate count until a per-phase budget caps it, which
     motivates a versioned serving-and-aggregation contract for the benchmark.

  Every claim is labeled by evidence tier (Source fact / Local measurement / Live observation /
  Triangulated / Inference / Testimony / Open hypothesis), and `ERROR`/`PENDING`/`COMPLETE`
  submission states are kept distinct. A rendered HTML version is in `paper/html/`.

- **[`attack.py`](attack.py)** — the `AttackAlgorithm` implementation submitted to the competition.
- **`paper/evidence/`** — the claim ledger backing the working note.

## Reproducing

The competition SDK (`aicomp-sdk`) is published by the organizers under MIT. A copy of **version
3.1.0** is vendored at `comp_310_backup/` for reproducibility. Note that the working note pins its
code citations to **3.1.2**, which is not included here — install it from the competition's Data page
to verify §4 line-for-line. `attack.py` implements
`AttackAlgorithmBase.run(env)`; the evaluator loads it from a Kaggle notebook that writes it to
`/kaggle/working/`. Submission kernels are generated by the build scripts under `dev/`.

## Responsible use

This work analyzes a **benchmark**: the "secret," sinks, and guardrails are competition fixtures in a
sandboxed harness, and defeating the scoring guardrail is the benchmark's intended, rules-sanctioned
objective. Findings are framed as lessons for benchmark and guardrail design, not as operational
techniques against real systems.
